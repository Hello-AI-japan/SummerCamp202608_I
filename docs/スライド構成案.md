## 2. コンセプト・作った理由（必須項目）

- **課題**: Hello AI! 運営メンバーは「誰が何を担当し、どこまで進んでいるか」がSlackの会話やミーティングの口約束に埋もれて分からなくなっている
- **結果として起きていた無駄**:
  - 「あれって誰がやってるんだっけ」という確認が何度も繰り返される
  - 抜け漏れとタスクの重複が発生する
- **解決の方向性**: 担当と進捗を1画面に集約し、確認のための会話そのものを不要にする
- **見える化の先にある行動変化**（評価軸として強調）
  - 「誰がやってる？」の確認Slackがゼロになる
  - 未着手タスクが一覧の先頭に出るので期限前に気づける
  - 割り当て時点で担当が確定し、同じ作業を2人がやる事故がなくなる

## 5. なぜそれを選んだのか（必須項目）

- **Supabase（PostgreSQL + Auth + RLS）**
  - 認証を自前実装せず、Supabase Authに寄せることでハッカソンの限られた時間を機能実装に集中できる
  - ロールベースの権限制御をDB層（RLS）で完結でき、UIだけに頼らない二重の権限チェックが実現できる
  - 5限で学んだRDBの知識を直接活用できる
- **Next.js / TypeScript / Tailwind CSS**
  - 型で担保しながら2名で並行開発しやすい
  - 情報量が多くAgentでの実装がスムーズ
- **Cloudflare Workers / Pages**
  - 要項必須の技術。無料枠でデプロイが速い
  - リスクも認識: Next.js × Cloudflareのデプロイ設定（OpenNext/next-on-pages）が最大の詰まりどころになりうるため、30分以上詰まったら「Vite + React + Hono on Workers」へ切り替える基準を事前に決めていた

## 6. Gitの活用内容・工夫点（必須項目）

- **ブランチ運用**: `main` / `feature/*` を分け、mainへの直接pushは原則禁止・PR経由＋レビュー1名以上の承認を必須化
- **型定義の早期合意**: 実装開始前に `types/task.ts`（Task型・Profile型・Status型）を2人で確定し、mainにマージしてから作業を分岐 → 結合時の衝突を回避
- **役割分担に沿った並行開発**: メンバーA（認証・RLS・API）／メンバーB（DBスキーマ・UI）を`feature/auth-api`・`feature/board-ui`で並行進行
- **実際に起きたトラブルと対処（工夫点として語れる実例）**:
  - GitHub Web UIからのファイル追加・削除操作でリモートとローカルの履歴が分岐（`diverged`）
  - `git fetch` で差分内容を確認した上で、コンフリクトが実質発生しない構成であることを見極め、`git rebase origin/main` で履歴をきれいな1本に整理
  - 「とりあえずmerge」ではなく、差分の中身を確認してから対処法を選ぶ判断を実践

## 7. Agent活用の工夫点（必須項目）

- **CLAUDE.md駆動開発**: プロジェクト概要・スコープ（Must/Should/Could）・データモデル・権限設計・禁止事項をCLAUDE.mdに明文化し、Claude Codeの実装判断のブレを防止
- **Plan Modeでの合意形成**: 実装前にPlan Modeで計画を出し、チームの確認を得てから着手するフローを徹底
- **危険領域の明文化**: RLSの無限再帰（`infinite recursion detected in policy`）など、事前に踏みそうな地雷と回避策（`SECURITY DEFINER`関数経由でのロール判定）をCLAUDE.mdに記載し、Agentが再発明せずに回避
- **権限まわりの自己検証ループ**: 「できるべき操作」と「できてはいけない操作」を必ずセットで検証する運用をCLAUDE.mdに明記（admin/member双方でログインし、他人のタスクを変更できないことまで確認）
- **詰まった時の撤退基準を事前合意**: Cloudflareデプロイ30分・RLS 1時間という時間制限をCLAUDE.mdに明記し、Agentが延々と同じ問題に固執しない設計
