2. 規約
2.1 必須事項
* Git、GitHub を用いること。（7限・8限を参照）
* Cloudflare を用いること。（5限・12限を参照）
* Claude Code などの AI を用いること。（10限を参照）
* 要件定義・詳細設計を行うこと。（11限を参照）
2.2 推奨事項
* worktree を用いて、agent を並列で動作させる。（8限を参照）
* GitHub Actions を用いて、自動テスト・PRレビューを行わせる。（8限・9限を参照）

2.3 成果物としての公開要件
* 外部に公開できる状態で、public かつ Hello AI! organization 上にリポジトリを作成すること。
* レポート（スライド）を提出すること（必須項目は本要項6章を参照）。
3. お題：「無駄をなくせる Web アプリ」
固定テーマは「無駄をなくせる Web アプリ」。ただしテーマだけでは初級〜中級には抽象的なため、以下の4つの切り口（シナリオ例）を提示する。チームはこの中から1つを選んでもよいし、これらを参考に独自の「無駄」を定義してもよい。いずれの場合も、要件定義フェーズで「誰の」「どんな無駄を」「なぜなくすのか」を明文化することを必須とする。
切り口
	シナリオ例
	「無駄」の例
	A. コミュニティ運営の無駄
	Hello AI! のようなサークル・勉強会運営を想定
	出欠確認が手作業／備品の貸出状況が分からない／誰が何を担当しているか分からない
	B. 学生生活の無駄
	受講者自身の日常を想定
	課題の締切管理が分散している／忘れ物が多い／授業やバイトのシフト調整に時間がかかる
	C. チーム開発の無駄
	今回のようなハッカソン・開発現場を想定
	レビュー待ちの可視化がない／タスクの重複／議事録や決定事項が流れて消える
	D. 暮らしの中の小さな無駄
	身の回りの生活シーンを想定
	在庫（食材・消耗品）の管理／割り勘計算／待ち時間の見える化
	お題選定のコツ：4時間で「動くMVP」に到達できる規模まで機能を絞ること。要件定義フェーズで Must / Should / Could を分け、Mustのみで完走できる設計にする。

6. Git・Agent活用の実践ポイント
6.1 Git運用（7限・8限の実践）
* ブランチ運用：main / feature-* の最小構成でよい。必ずPull Requestを経由してmainにマージする
* コミットは小さく分ける（1機能・1修正＝1コミットを意識）
* レビューはチームメンバー1名以上の承認を必須にする
* GitHub Actionsで自動テストを回し、可能であればClaude Codeを使ったAIレビューをPRに組み込む（推奨事項）
6.2 Claude Code / Agent活用（10限の実践）
* プロジェクト開始時に /init でCLAUDE.mdを生成し、技術スタックやルールを明文化する
* 要件定義〜設計はPlan Modeで壁打ちし、実装前に計画をチームで確認する
* フロント担当・バックエンド担当・テスト担当のようにSubagent／workflowで役割を分け、並列に作業させる（推奨事項）
* 2回失敗したら/clearしてより具体的な指示で仕切り直す（コンテキスト管理）
* 検証手段（テスト・スクリーンショット比較など）を必ずAIに与え、自己検証させる

9. 運営メモ・注意事項
* 要件定義30分は短いため、当日は「お題の切り口を選ぶ→誰のどんな無駄かを1文で決める→Must機能を3つ以内に絞る」の順で時間管理すると良い
* 中間チェックポイント（1時間経過・3時間35分経過）でファシリテーターが各チームを巡回し、スコープが肥大化していないか確認する
* GitHub Actionsの利用料金・プライベートリポジトリの料金体系は事前に確認しておく（8限の学習事項）
* Gitワークツリーを使う場合、削除時は物理フォルダの削除だけでなくGitコマンドでの削除も徹底する
